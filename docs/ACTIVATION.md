# Activate the Unity build

GitHub access and Unity activation are separate. The repository connection can publish code, but it does not provide a Unity license or sign in to your Unity account.

## GitHub Actions with Unity Personal

Use the Unity account that owns the license. A Gmail address used for GitHub is not automatically a Unity account.

1. Install [Unity Hub](https://unity.com/download) on your computer and sign in to Unity.
2. In Hub, open **Preferences → Licenses → Add** and activate your eligible Personal license.
3. Locate the license file generated by Hub:

   | Computer | License file |
   | --- | --- |
   | Windows | `C:\ProgramData\Unity\Unity_lic.ulf` |
   | macOS | `/Library/Application Support/Unity/Unity_lic.ulf` |
   | Linux | `~/.local/share/unity3d/Unity/Unity_lic.ulf` |

4. Open [UO → Settings → Secrets and variables → Actions](https://github.com/bralynnb/UO/settings/secrets/actions) and add repository secrets:

   | Secret | Value entered directly in GitHub |
   | --- | --- |
   | `UNITY_LICENSE` | Entire contents of your activated `.ulf` file |
   | `UNITY_EMAIL` | Your Unity account email |
   | `UNITY_PASSWORD` | Your Unity account password |

5. Open [Build Unity browser game](https://github.com/bralynnb/UO/actions/workflows/unity-webgl.yml). Choose **Run workflow**, or **Re-run failed jobs** on the latest activation failure.

Do not send credentials or the license file in chat, commit them, or upload them as workflow artifacts. The activation check reports only which secret names are missing. It does not read back their values.

These are the [current GameCI Personal activation instructions](https://game.ci/docs/github/activation/). If your Hub/account does not generate a compatible `.ulf`, use the local build below; an empty license file or an old `.alf` manual-activation tutorial will not activate this workflow.

## Existing Unity Pro license

Use `UNITY_EMAIL`, `UNITY_PASSWORD`, and `UNITY_SERIAL` instead. Do not configure both `UNITY_SERIAL` and `UNITY_LICENSE`; the workflow rejects mixed activation methods. Follow [GameCI's Professional license instructions](https://game.ci/docs/github/activation/#professional-license). The builder handles activation and returning the allocation.

## Build locally with an activated Editor

This path does not require storing Unity credentials in GitHub.

1. Install **Unity 6000.0.62f1** with **Web Build Support** through Unity Hub and activate it.
2. Open the UO project. Choose **TSFM → Build browser game**.
3. In a terminal in UO, run `npm ci` and `npm run check:build` with Node 24.
4. Start or restart the server with `npm start`, then open `http://localhost:8080`.

Batch commands are in [DEPLOYMENT.md](DEPLOYMENT.md). Compilation can reveal Unity API or build issues that source/server checks cannot catch. A green activation configuration check means the credentials are present; a successful **Unity - Builder** step is required before claiming the game compiled.

## What a successful workflow produces

The workflow runs server tests, activates Unity, compiles the WebGL client, checks the generated loader/framework/data/WebAssembly files, and builds the deployment container. Its **tsfm-unity-browser-and-server** artifact contains `tsfm-deploy.tar.gz` plus a checksum.

The artifact becomes available only after compilation succeeds. Publishing that bundle to a persistent host and completing a browser playtest are separate steps; see [hosting instructions](DEPLOYMENT.md#railway).
